# 把 Kalodata 的导出放这里

## 为什么是导 CSV，不是接口

2026-11-19 实测：Kalodata **没有开放 API**。`api.kalodata.com` 和 `open.kalodata.com`
都不解析（DNS 立即失败），官网只卖网页/App 的账号席位。所以「拿到 key 就每天自动拉数」
这条路不存在，数据出口只有网页上的导出按钮。

顺带更正一个名字：B 在 11-17 通话里说的是 **Koladata**，那个域名不存在，四个子域全连不上。
正确的是 **Kalodata**，`www.kalodata.com`，11-19 实测 200。

## 怎么放

1. Kalodata 里筛好条件：站点 Brazil，类目按穿戴甲/美甲走，时间窗选近 7 天或 28 天
2. 点导出，格式选 **CSV**。如果有「Excel 兼容 / 带引号」的选项，一定选上
   （原因见下面「已知会丢数据的情况」）
3. 文件名带上日期，直接丢进这个目录：

```
pipeline/inbox/kalodata_20261119.csv
pipeline/inbox/kalodata_20261126.csv
```

4. 跑 `python pipeline/run.py`。不用改代码，表头会被自动识别。

## 认哪些表头

必需两列：**商品名** 和 **价格**。其余有就用，没有就空着。

| 字段 | 认的写法（不分大小写，取第一个命中的） |
|---|---|
| 商品名 | 商品名称 / 商品标题 / 商品名 / 产品名称 / Product Name / Nome do produto |
| 价格 | 商品价格 / 售价 / 现价 / 价格 / Sale Price / Price / Preço |
| 销量 | 月销量 / 销量 / 已售 / Units Sold / Vendas |
| 销售额 | 销售额 / 成交金额 / GMV / Revenue / Faturamento |
| 评分 | 商品评分 / 评分 / 星级 / Rating / Avaliação |
| 店铺 | 店铺名称 / 店铺 / 商家 / Shop / Loja |
| 平台 | 平台 / Platform / Plataforma |
| 链接 | 商品链接 / 链接 / URL / Link |
| 日期 | 采集日期 / 统计日期 / 日期 / Date / Data |

表里带「平台」列就按列走（TikTok Shop / Shopee / Mercado Livre / Amazon 都认）。
没有这一列就统一记成 TikTok Shop，页面的数据源说明里会写「无平台列，按 TikTok Shop 记」。

## 数字格式

巴西写法已经处理过了，不用手动清理：

```
R$ 29,90      -> 29.90        R$ 1.234,56  -> 1234.56
R$ 1.099,00   -> 1099.00      1,234.56     -> 1234.56
1.2万          -> 12000        12K          -> 12000
```

判定规则只看分隔符后几位：后 3 位当千分位，后 1 到 2 位当小数点。
这条规则的前提是巴西价格永远写两位小数，三位小数在电商报价里不存在。

## 已知会丢数据的情况

**字段里有逗号却没加引号。** 比如这样一行：

```
Produto A,R$ 45,90,1200
```

`R$ 45,90` 会被切成两列，整行往后错一位，价格跑到销量列、销量跑到 GMV 列，
数据看着有、其实是错的。适配器现在的处理是**直接丢这一行并记数**，
页面上会写「丢弃错位行：xxx.csv N 行」，不会让错位的数据混进报告。

所以导出时选带引号的格式。如果整份文件都报错位，说明它压根没加引号，
把格式换掉重导，不要试图在 Excel 里手工补。

## 每天怎么更新

`.github/workflows/daily.yml` 每天北京时间 20:00 跑一次（巴西时间 09:00）。
它只做一件事：读这个目录里已有的 CSV，跑管线，提交当天的快照和日报。

**它不会自己去 Kalodata 拉数据。** 因为 Kalodata 不给接口，这是事实，不是还没做。
真要每天自动，只有两条路：让对方开商务 API，或者换一个有 API 的数据源。

在拿到自动源之前，这个目录需要有人每天或每周放一次新文件。
历史文件不用删，留着才能算价格异动和趋势；同名会被覆盖，所以文件名带日期。
